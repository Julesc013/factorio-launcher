# FacMan 0.1.0-alpha.4 foundation candidate

Status: implementation candidate; unsigned, unpublished, and unsupported.

Alpha.4 is the forward-only convergence release after the immutable alpha.3
distribution. It keeps 0.1 deliberately bounded while adopting the product
shape intended for 1.0.

## Candidate shape

- One public GUI identity, `FacMan`, and one terminal host, `facman`.
- Machine JSON, human CLI, and `facman tui` share one command and result model.
- Two package adapters per claimed platform: portable and setup, both produced
  from the same verified product stage.
- One deterministic `facman.resources` payload for runtime contracts, content,
  policy, generated indexes, release identity, and provider locks.
- Exact Universal Launcher and Universal Setup revisions from detached,
  marker-owned external provider workspaces.
- Windows x64 as the reference candidate; macOS Intel x64 AppKit and Linux x64
  GTK/X11 as experimental previews.

The admitted local-first foundation covers workspace/doctor, installation
discovery and read-only registration, isolated instances, profiles, local
mods/modsets, saves/snapshots, readiness and launch previews, sessions and Last
Run, recovery, redacted diagnostics, resource/package verification, and only a
fresh FacMan-owned managed-install target.

## Authority still pending

Machine qualification does not authorize real Factorio execution, a live
managed installation, experiential accessibility acceptance, signing,
notarization, upload, publication, or support. Those gates require separate
human and operator receipts bound to the exact candidate bytes. No alpha.4 tag
or public release is created by the implementation WorkUnit.

Network Mod Portal acquisition, credential storage, automatic update, daemon
or remote administration, plugins, a public provider SDK, server execution,
store mutation, Apple Silicon/universal macOS, Wayland-native behavior, and
general Linux distribution support remain explicit deferrals.

# Changed files

This work unit closes the alpha.5 foundation programme around one exact,
non-authorizing product-candidate proof and reconciles the repository with the
larger 0.1 vision.

- `release/index/`, its release schemas, strict workflow, and validators now
  bind the exact promotion topology, hosted run, artifacts, provider pins,
  package-equivalence evidence, revision-scoped qualification, and all-false
  authority ceiling in one closed alpha.5 receipt.
- Release, architecture, product, roadmap, support, package, naming, GUI, CLI,
  TUI, and maintenance documentation now share one honest state model: 0.1 is
  architecturally 1.0-shaped, while human, managed-install, Play, signing,
  notarization, publication, and support gates remain open.
- The support and package models distinguish Windows machine qualification
  from pending human/support approval, distinguish macOS/Linux semantic
  preview qualification from full parity, and keep Qt6 under separate later
  admission rather than treating it as an automatic 1.0 dependency.
- Package producers and their TCK now preserve the canonical cross-platform
  payload law. The receipt uses portable `facman-development://` custody
  locators, so packaged release metadata cannot expose an operator or machine
  path.
- Generated WinForms command and native version projections were regenerated
  from the changed release truth. The project-state generator's alpha.5 logic
  was extracted into `tools/project_state_alpha5.py`, reducing the primary
  generator below its existing source-size budget without raising that budget.
- Release identity, programme, foundation readiness, source-closure, plan,
  package, schema, AIDE, and current-truth tests were extended to fail closed
  on circular qualification, stale candidate inheritance, unsupported support
  claims, unbound receipts, and machine-dependent package metadata.
- The completed Ultimate and Beta work units were verified, closed, and moved
  from `.aide/queue/active/` into the single dated history collection. The
  queue index, project memory, plan views, and current-state projections were
  regenerated from canonical records.
- The archive-index receipt now binds the declared `text_lf_v1` digest rather
  than Windows working-tree CRLF bytes, with an exact schema constant and a
  regression proving identical LF/CRLF verification across checkouts.

The changed path set is contained by the active task's `allowed_paths`. No
forbidden `.git/**` or `.aide.local/**` content is part of the change. Native
builds, packages, candidate downloads, and test evidence were written only to
marker-owned external development roots; no persistent in-checkout `build`,
`dist`, `out`, or `tmp` root was introduced.
